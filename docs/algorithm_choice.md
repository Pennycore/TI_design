# 算法选择记录

## 第一版推荐

采用双处理器分工：

- MSPM0：实时控制层，周期 5 ms 左右，完成灰度读取、循迹估计、PID、电机输出和安全停车。
- K230：视觉层，运行摄像头小钢球识别，只发送目标坐标、半径、置信度和稳定标志。

## 循迹算法

灰度传感器使用 I2C 连续读取 8 路模拟量命令 `0xB0`。如果传感器固件为 V3.6 及以上，初始化时启用归一化 `0xCF=0xFF`。手册说明归一化后白场约为 255、黑场约为 0，所以黑线循迹时使用 `signal = 255 - analog[i]`。

没有选用手册第 6 章的 CLK/DAT 串行通讯，因为它只能读 8 路数字量，不能读模拟量、版本号和错误信息。第一版循迹需要模拟量质心，I2C 更合适；K230 和 MSPM0 之间才使用常规 UART。

位置估计使用 8 路加权质心：

```text
weights = [-3500, -2500, -1500, -500, 500, 1500, 2500, 3500]
position = sum(signal[i] * weights[i]) / sum(signal[i])
```

`position > 0` 表示线偏右，控制器让左轮更快、右轮更慢；`position < 0` 表示线偏左。

## 小钢球识别算法

第一版 K230 脚本使用传统视觉：

- 摄像头采集 QVGA RGB565。
- 优先用 `find_circles()` 找圆形候选。
- 根据半径、圆心位置、检测强度打分。
- 连续几帧稳定后设置 `stable` 标志。
- 通过 UART 发给 MSPM0。

这个方案的优点是上手快、无需训练、比赛现场能直接调阈值。缺点是强反光、杂乱背景或球体半遮挡时可能误检。

## 何时升级到模型检测

如果出现下面情况，建议把 K230 视觉升级为 YOLOv8n/YOLO11n 量化后的 kmodel：

- 场地背景里有很多圆形高亮物。
- 钢球大小变化大，传统圆检测经常丢。
- 需要同时识别钢球、边界、障碍物或容器。
- 现场光照变化导致传统阈值频繁重调。

升级路线：先用当前脚本采图，标注 300 到 1000 张，训练轻量 YOLO，部署到 K230。MSPM0 侧串口协议不用改，只需 K230 仍发送相同 `VISION_BALL` 帧。
