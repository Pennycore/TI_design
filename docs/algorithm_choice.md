# 算法选择记录

## 总体分工

采用双处理器分工：

- MSPM0：实时控制层，完成灰度读取、循迹估计、PID、电机输出、安全停车。
- K230：视觉层，运行摄像头钢球识别，只把目标坐标、半径、置信度和稳定标志发给 MSPM0。

这样做的好处是车控实时性留在 MSPM0，视觉算法可以在 K230 上独立迭代。

## 灰度循迹

当前 `car_control/` 使用感为灰度传感器的 CLK/DAT 串行数字量读取方式。它的优点是连线少、代码已经落地；缺点是只能得到 8 路黑白数字量，不能得到更细的模拟灰度。

后续如果需要更平滑的线位估计，可以切换到 I2C 读取 8 路模拟量。黑线循迹时建议使用：

```text
signal = 255 - analog[i]
weights = [-3500, -2500, -1500, -500, 500, 1500, 2500, 3500]
position = sum(signal[i] * weights[i]) / sum(signal[i])
```

## 10mm Q235 钢球识别

推荐深度学习模型：

```text
YOLO11n, input 416x416, one class: steel_ball
```

理由：

- 10mm 钢球在画面中是小目标，416 输入比 320 更容易保住细节。
- YOLO 检测天然支持多目标，一张图里多个钢球会输出多个框。
- 单类别 `steel_ball` 训练成本低，第一轮 700 张左右就可以开始迭代。
- 相比传统圆检测，YOLO 更抗反光、阴影、背景圆形物体和半遮挡。

如果 K230 实测帧率不够，再把输入尺寸降到 320x320 重新训练、导出和转换。

## 串口策略

K230 端同时保留两个输出：

- `0x10 VISION_BALL`：主目标，一个最适合当前车控追踪的钢球。
- `0x11 VISION_MULTI_BALL`：最多 4 个钢球的列表，给后续多球策略使用。

MSPM0 初期只需要处理 `0x10`，这样车能先跑起来；等机构和比赛策略明确后，再决定是否使用 `0x11`。

## 数据集重点

标注类别只建一个：

```text
steel_ball
```

标注规则：

- 画面里所有可见钢球都要标，不能只标最近或最大的那个。
- 多球场景至少准备 150 张，建议包含 2 到 5 个球。
- 必须有无球负样本，用来压低反光点、螺丝、圆孔等误检。
- 远距离小球、边缘小球、暗光和强反光样本要专门补。
